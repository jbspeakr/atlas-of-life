# Evolution

Only measured experiments belong here. Optimisation uses the ordered objective in the brief; correctness, publication safety, accessibility and network purity are never traded away. Visual changes require explicit approval. Failed checks are fixed, not retried into acceptance.

## Calmer camera motion and regional depth

The owner reported that the globe flight felt like a shaky steadicam and requested regional depth. Replaced the offset waypoint zigzags and independent sinusoidal zoom with deliberate pan/dolly/hold shots. Quintic minimum-jerk interpolation reaches zero velocity and acceleration at joins. The center stays fixed during every zoom; inter-region travel happens at zoom 2.25, after pulling back. Regional reveals reach zoom 5 in portrait/landscape and 4.75 in square, where the app's regional fills and outlines are fully visible. Both regions get a 1.5-second hold. The closing shot now pulls back over the second region instead of reversing course to force a loop.

The first published place (or `--place`) anchors the first region; spherical distance selects the most distant representative for the second. The normal-data run shows Germany around Berlin, then Attica/Greece around Kalamos. Removed capture-time variable text anchors so labels no longer hop between sides during motion. Production UI, map styles, data and basemap configuration remain unchanged. Regional shots use the normal archive's global z0–6 coverage, not its city-extract windows.

Verification: all 57 tests passed, including 20 recording cases covering settled velocity/acceleration, locked-center regional zooms, monotonic broad transfers, holds, dateline handling, one-entry data and frame bounds. TypeScript and targeted lint passed. The normal three-format run completed in approximately 324 seconds and saved six files in `recordings/cinematic-regions/`. Independent ffprobe/MP4/PNG inspection confirmed each requested resolution, 720 decoded frames, 24 seconds, 30 fps, silent H.264/yuv420p, BT.709 metadata, fast-start atom order and full-resolution posters. All three posters and eight samples per format were inspected. Portrait and landscape were played end-to-end in Chromium; both reached 24 seconds with all 720 source frames present (instrumented playback reported two and one dropped display frames respectively, not missing encoded frames). Regional geography and attribution remained visible, without the previous city-extract gaps. Temporary inspection frames and servers were removed after verification.

Regional holds reuse their settled PNG rather than recapturing an unchanged camera; every moving sample still settles and captures independently. A further normal-data portrait run exercised this capture path through all 720 frames and passed the encoder and independent frame-count gates. Its held-frame poster was byte-identical to the already inspected regional poster. No partial media or occupied recorder port remained.

## Immersive globe overview flight

At the owner's request, replaced the single-city descent with a 24-second moving globe overview. The flight reveals the sphere from the side, passes geographically varied public entries, gently pulls closer, and returns to the opening camera. It never reaches zoom 2. Route representatives prefer different countries and geographic spread, using spherical distance rather than raw longitude differences; `--place` now sets the route anchor. The current default route is Berlin → Lampeland → Paris → Kalamos. A one-entry atlas still gets a moving globe flight without fabricated destinations.

The recorder exposes the existing published gold pins at overview scale and labels up to four representatives with normal collision handling. These changes are scoped to each capture context; no production UI, stylesheet, source geography or basemap configuration was changed. City dialogs and high-zoom shots were removed. Every frame is rendered rather than stretching static holds, and the poster captures the middle of the flight.

Verification: all 53 unit tests passed, including 16 globe-route/boundary/dateline/range cases; TypeScript and targeted lint passed. A normal-data run produced all six files in `recordings/globe-flight/` in approximately 397 seconds. Independent inspection confirmed 720 decoded frames, 24 seconds, 30 fps, H.264/yuv420p, no audio, all BT.709 tags and a fast-start `moov` atom before media data. Portrait, square and landscape retained their native 1080×1920, 1080×1080 and 1920×1080 dimensions, including posters.

Inspected all posters and samples at 0, 4, 8, 12, 16, 20 and the final frame; played the portrait movie end-to-end in Chromium, which reported 720 video frames and zero dropped frames. The broad route no longer exposes the previous city-extract gaps. Opening/closing decoded mean RGB differences were 0.171, 0.208 and 0.135 on the 8-bit scale, consistent with visually matching loop endpoints despite lossy encoding. Pre-roll initially exposed a globe hit-testing issue: a full-viewport feature query missed visibly rendered pins across the horizon. Querying each pin's actual projected point fixed the check without weakening it. Help, invalid format and an existing empty output directory remained side-effect-free. A Paris-anchored run followed a different public route, then Ctrl-C exited 1 with no remaining owned children, no media and port 4180 released.

## Automated marketing recorder

Added `npm run record`: three independently rendered responsive formats, a deterministic 720-frame world → region → city → world camera timeline, the real selected-place caption during seconds 15–19, and lossless PNG streaming into silent H.264 movies with posters. The command reuses the verification server/readiness/camera helpers, builds ordinary public data, and owns process cleanup without changing production UI or camera APIs.

Verification: all 51 unit tests passed, including 14 new camera boundary/dateline/range cases; TypeScript and targeted recorder lint passed. A real bundled Berlin fixture run produced six outputs at 1080×1920, 1080×1080 and 1920×1080. Independent ffprobe checks confirmed 720 decoded frames, 30 fps, 24 seconds, H.264/yuv420p and no audio for every movie. FFmpeg 9 initially dropped primaries/transfer metadata despite output flags; explicit frame tags fixed this, and a second three-format run passed all BT.709 tag gates. Posters were byte-identical to the visually inspected originals.

Inspected all three posters and frames at 0, 5, 10, 14, 17, 21 and 23 seconds, and played the portrait movie in Chromium. The square caption, pin, timeline and attribution fit; map-region pixel differences across caption entry were below 0.003 per RGB channel (8-bit), showing no camera jump. Help, invalid format and existing-directory rejection left build/data/media hashes and modification times unchanged. Invalid image input failed in 811 ms; a producer error failed in 2 ms; both closed the iterator and left no media. The first Ctrl-C smoke exposed Playwright's default forced exit bypassing partial-file cleanup. Disabling its signal handlers in favor of the CLI's owned lifecycle fixed the reproduction: exit 1, no remaining owned processes, no media, and port 4180 successfully rebound.

The original normal-data city tour selected Berlin from the owner's 18 public places and passed its metadata gates, but required wider archive coverage: tile `10/550/335` contained 176,643 bytes while `10/549/339`, near its high-zoom return position, was absent. That visual blocker belongs to the city-close-up experiment. The subsequent owner-approved globe overview above avoids those zoom levels and was verified with the same unchanged remote archive.

## Quieter map controls and contextual discovery

Removed the blurred country glow and mismatched fine-outline source in favor of subdued, matching fill/outline geometry. North-up navigation now excludes mouse, keyboard and touch rotation/pitch, and the camera no longer rotates on its own after ignition. Compact World navigation includes Alt+W; the timeline, title and selected-place caption take less space.

Replaced the persistent chronological list with an on-demand, map-aware directory: In view / All places, city/region/country search, year-aware results and six-row pages. The global scope keeps distant places discoverable; projection round trips exclude the globe's rear hemisphere.

Verification: TypeScript, lint and all 37 unit tests passed. Desktop and mobile views were inspected in Chromium. An isolated browser smoke run reached all 18 current places through pagination, exercised search and selection, checked viewport and rear-hemisphere exclusion, synchronized the directory and map with the year slider, tested Alt+W including its editing guard, and confirmed focus recovery from both list selection and a rendered pin. Keyboard, right-drag and two-finger rotation kept bearing and pitch at zero. Desktop, open-directory and mobile axe checks reported no WCAG A/AA violations; the 320px layout had no horizontal overflow. Existing runtime scenarios were updated for the collapsed directory and stationary camera. Visual baselines and performance approval were not regenerated.

## Date/city/country authoring and geographic discovery

The owner dataset exposed incompatible geographic identifiers: Kalamos's Nominatim `GR-A2` versus gbOpen Attica `GR-AT` and Natural Earth `GR-A1`; Lampeland's `NO-33` versus the pinned 2022 Viken `NO-30`; and Italian macro-area polygons with empty ISO codes. The pipeline now discovers implicit membership spatially and keeps provider identifiers separate from geocoder provenance. It does not invent country-specific aliases or drop usable polygons lacking ISO codes.

City entries now need only country, city and dates. Stable IDs and labels are generated; tags and tag filtering are removed. Settlement geocoding uses the place's own name and upstream alternatives instead of a containing municipality; Hollenbeck's cached metadata was corrected from Harsefeld without moving its already-correct point.

Verification: 37 tests passed; all 19 quick-verification checks passed, including lint, TypeScript, fixture build, publication safety and budgets. The real owner build emitted 17 visits/pins, 14 regions and 8 countries. All 17 cities were selected in the production browser and their actual rendered pins and geography captions checked. Kalamos's generated deep link survived reload; the timeline changed its visibility from 0 in 2024 to 1 in 2026, and Escape restored focus. This was a functional browser smoke check, not a full performance or baseline-image approval run.

The owner's larger geography totals 592,249 gzip bytes, above the 400,000-byte target but below the unchanged 1,000,000-byte hard limit. Provider geography remains explicitly versioned: Lampeland displays historical Viken, and Reggio Calabria displays Italy's supplied Sud macro-area. Basemap street-detail coverage is still determined by the deployed tile archive, independently of visit pins.

## Experiment: remove unused sprite loading — reverted

Hypothesis: with no `icon-image` or pattern consumers in the generated style, removing its sprite URL would reduce first-view requests/bytes without a visual or performance regression. Only sprite loading changed (`scripts/build-style.ts` and `src/map/create-map.ts`); vendored assets stayed intact. The experiment was committed as `376120d` and measured with quick verification followed by a full run. The before measurement was the committed green baseline.

| Metric                          |              Before |                After |     Delta |
| ------------------------------- | ------------------: | -------------------: | --------: |
| Hard failures                   |                   0 |                    0 |         0 |
| p95 frame time, five-run median |           18.147 ms |            23.548 ms | +5.401 ms |
| p95 spread                      | 5.464 ms (unstable) |             2.874 ms |         — |
| First-view transferred bytes    |             946,789 |              929,367 |   −17,422 |
| First-view requests             |                  14 |                   12 |        −2 |
| Visual diff pixels              |                   0 | 39,675, in city view |   +39,675 |
| Direct / runtime dependencies   |              30 / 6 |               30 / 6 |         0 |

**Reverted.** Fewer requests cannot buy a worse measured p95 or an unapproved image change. Timing noise was already flagged in the baseline, so this is not a claim of a proven causal slowdown; it is a refusal to accept an experiment that failed the stated acceptance criteria. No threshold or visual baseline was weakened, and no retry was used to manufacture a passing result. The original sprite-loading behavior is restored.

## Correcting first-view visual capture settling

After restoring the original sprite behavior, the same 39,675-pixel city difference recurred. It was therefore not evidence of a sprite-caused visual change. A focused camera experiment showed that the first city capture differed, waiting one second did not change it, but an additional post-idle render matched the approved image exactly. Merely changing zero-duration `easeTo` to `jumpTo` was insufficient on a cold view. The capture harness now positions static views with `jumpTo`, observes idle, advances one animation frame, and flushes a subsequent idle render before its single comparison. Three successive diagnostic captures, including the cold view, then each differed by **0 pixels**. Timed performance choreography is unchanged; no threshold or approved baseline changed, and comparisons are not retried until they pass. The sprite experiment remains reverted because it also failed its measured p95 acceptance criterion.
